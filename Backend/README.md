# Campus Grievance Intelligence — Backend

## What's here
- `models.py`  — database schema (complaints, locations, departments, issue clusters)
- `seed.py`    — generates 180 realistic fake complaints so the dashboard has data to show
- `main.py`    — the API server (FastAPI) that the dashboard/chat interface will call
- `requirements.txt` — Python packages needed

## Setup (run these in order, in a terminal, inside this folder)

1. Make sure you have Python 3.10+ installed. Check with:
   python3 --version

2. Create a virtual environment (keeps this project's packages separate from everything else on your machine):
   python3 -m venv venv

3. Activate it:
   - Mac/Linux:   source venv/bin/activate
   - Windows:     venv\Scripts\activate

4. Install the required packages:
   pip install -r requirements.txt

5. Generate the database (creates campus_grievance.db with 180 fake complaints):
   python3 seed.py

   You should see: "Seeded 180 complaints (32 restricted...)"

6. Start the server:
   uvicorn main:app --reload --port 8000

   Leave this terminal window open — the server runs as long as this is running.

## Check it worked

Open a browser and go to:
   http://localhost:8000/api/analytics/kpis

You should see JSON like:
   {"total_complaints":148,"pending":63,"high_priority":54,"avg_resolution_days":1.89}

Also try:
   http://localhost:8000/docs

This gives you an interactive page (auto-generated by FastAPI) where you can see and test
every endpoint without writing any code — click an endpoint, click "Try it out", click "Execute".

## If something goes wrong

- "command not found: python3" → Python isn't installed, or use `python` instead of `python3`.
- "No module named fastapi" → you forgot step 3 (activate the venv) or step 4 (install).
- "Address already in use" on step 6 → something's already running on port 8000. Either close
  it, or run with a different port: uvicorn main:app --reload --port 8001
- Need to start fresh? Delete campus_grievance.db and re-run seed.py.

## Next time you want to work on this

You only need steps 3 and 6 again (activate the venv, start the server) — steps 1, 2, 4, 5
are one-time setup, unless you delete the folder or the database.
